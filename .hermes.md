# Hermes project rules — rosetta

Hermes: when working in this repo, adopt this behavior. `AGENTS.md` (repo
root) is the operating manual — commands, layout, invariants, boundaries.
This file adds Hermes-specific conduct; do not duplicate it, layer on it.

## Session behavior

- Read `AGENTS.md` before your first code edit in a session. Build/test
  commands live there and are verified — do not re-derive them.
- `AGENTS.md` §Non-negotiable invariants is hard boundary discipline: the
  public leaderboard is real-data-only, live and synthetic rows share
  snapshot files and are separated only by the `is_synthetic` column, and
  the Stats API ingest must use `playerPool=ALL`. Decline requests that
  violate these with a pointer to the rule unless the user overrides
  explicitly.
- Data refreshes (`make live-data`, `fetch-*`) hit live external sites and
  take minutes — confirm scope before kicking one off, and remember
  `factors.json` must be refit afterward (`make leaderboard` won't).

## Skill routing (Hermes skills — load with skill_view before the task)

Run Hermes for this repo via the repo-root **`./dev`** script — the
primary entrypoint for development here. It is idempotent: it creates the
**rosetta profile** (`hermes --profile rosetta`), prunes irrelevant skills
from that profile via `skills.disabled`, bootstraps the repo-local project
skills in `.hermes/skills/`, and ensures the repo is trusted — then drops
you into a session. Subcommands: `./dev setup` (bootstrap only),
`./dev doctor` (verify environment), `./dev -q "prompt"` (one-shot; all
other args pass through to hermes). The default profile keeps the full
catalog for everything else.

| Task in this repo | Load skill |
|---|---|
| Writing any new feature or fix | `test-driven-development` — tests first; tests live in `tests/` and run offline |
| A bug that isn't immediately obvious | `systematic-debugging` — root-cause before fixing |
| Before committing code changes | `requesting-code-review` — static scan → gates → independent reviewer → fix loop. Mandatory for multi-file changes |
| Messy milestone chunk just landed | `simplify-code` — run after each milestone, not mid-milestone |
| Validating an unknown design before building | `spike` — throwaway experiment first; findings go in `docs/`, never half-landed code |
| Executing an approved plan (multi-task) | `subagent-driven-development` — fresh implementer subagent per task, two-stage review |
| Plan interview before implementation | `grill-me` — invoked by the user, but expect it even after "go" |
| "How big is the codebase" metrics | `codebase-inspection` |
| PRs, issues, reviews on the GitHub repo | `github` |
| Substantial autonomous/multi-step work | `unlazy` — keep working to verified done, no stubs |
| Hermes config/theming questions | `hermes-agent` |
| Bash work in `./dev` or hook scripts | `shell-portability` |

Negative controls — do NOT load a skill for a near-neighbor ask:

- A one-off data question ("how many KBO rows do we have") ≠ a full
  `codebase-inspection` run; answer directly with a quick count.
- An ordinary reproducible bug ≠ `spike`; spike is for validating an
  unknown *design* before building, not debugging.
- A failing test in existing code ≠ `test-driven-development` from
  scratch; reproduce, then `systematic-debugging`.
- A stale `factors.json`/`leaderboard.json` is a Makefile refresh, not a
  modeling task — no skill needed.
- Doc/comment wording tweaks load no skill at all.

## Hooks (rosetta profile)

Configured in `~/.hermes/profiles/rosetta/config.yaml`, scripts in
`~/.hermes/agent-hooks/`:

- `rosetta-git-guard.sh` — pre_tool_call on `terminal|execute_code`,
  fail_closed: blocks mutating git (push/pull/commit/merge/...); read-only
  git passes. Commit through the user or with explicit approval.
- `rosetta-formatter.sh` — post_tool_call on `write_file|patch`: runs
  `ruff check --fix` + `ruff format` on edited `.py` files when the repo's
  `.venv/bin/ruff` exists. Guarded no-op until the venv exists.
- `rosetta-evidence.sh` — post_tool_call on `terminal`: appends a compact
  JSONL line per command to
  `~/.hermes/agent-hooks/rosetta-evidence.jsonl`.
- `rosetta-inject-git-status.sh` — pre_llm_call: injects branch +
  dirty-file status when the session cwd is inside this repo
  (matches origin `harlanljones/rosetta`).

First session start may prompt for per-profile hook allowlist consent, or
run `hermes --profile rosetta --accept-hooks` once.

## Engineering gates (do these yourself, unprompted)

- Every change: `make test && make lint` green before declaring done.
- After any ingest change: refresh snapshots, delete
  `data/outputs/factors.json`, rebuild, and verify the leaderboard JSON
  says `data_mode: "real"` with populated `source_counts` and factors
  `links` carrying real sample sizes.
- Never commit live credentials, raw Savant dumps, or hand-edited
  snapshot data.
